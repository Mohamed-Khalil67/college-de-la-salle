Collège de la Salle, Daher, Cairo

CDLS architecture map

One school platform in three parts: an Angular web app, a NestJS API on PostgreSQL, and a shared package that holds the contract between them. Read the tabs left to right, from the outside in.

What runs where

Everyone reaches the school through one of two entries. The web container serves the pages, and the API is the only thing that touches the database.

How the Angular app is layered

A layer may import from the layers below it and never from above. architecture.spec.ts fails the test run if a file breaks a rule.

  • Role spaces are imported only by themselves and by the app routes.
  • A feature's shared/ folder is private to that feature. Code needed by two features moves to shared/.
  • Strict TypeScript: no any, indexed access is checked, and Angular's extended diagnostics are errors.
  • Standalone components, signals, zoneless change detection, Signal Forms for new forms.

Database in three groups

Roughly forty tables, split by what they are for. Each line names what the table links to. Every column is in apps/api/prisma/schema.prisma.

People, years, classes

Who exists, and which class they are in this year.

  • USERrole, status. Parent of STUDENT, TEACHER, sessions, notifications
  • STUDENT→ USER, SECTION
  • TEACHER→ USER. Flag: coordinator
  • SCHOOL_YEARstart, end, archived at
  • SECTIONa stream of the school, unique code
  • SCHOOL_CLASS→ SCHOOL_YEAR, SECTION, next class for rollover
  • ENROLLMENTSTUDENT in a SCHOOL_CLASS for one year
  • CLASS_SUBJECTSCHOOL_CLASS + SUBJECT. The coefficient lives here
  • PERIODterms per year and section
  • SECTION_CHANGE_REQUESTstudent asks, admin decides

Timetable, groups, rooms

Weekly rules, one-off changes, and the index that blocks clashes.

  • ROOMkind, capacity
  • TIMETABLE_SLOTweekday, week parity → CLASS_SUBJECT, TEACHER, ROOM, ACTIVITY_TYPE, optional GROUP
  • SLOT_EXCEPTIONcancel, move or change room on one date
  • GROUP / GROUP_MEMBERa class split into divisions of students
  • ACTIVITY_TYPEcours, TD, TP or a teacher's own type
  • OCCUPANCYtime range per room, teacher, class and group. A PostgreSQL EXCLUDE constraint refuses overlaps, so no code path can double-book

Work, grades, messages

What teachers assign and students receive.

  • EVENThomework, exam or session → ACTIVITY_TYPE, PERIOD, SCHOOL_CLASS, author TEACHER
  • ASSESSMENT_TARGET« Assigner à »: a group or a single student
  • GRADEEVENT × STUDENT, score, published flag
  • HOMEWORK_COMPLETIONstudent ticks an EVENT as done
  • ATTENDANCEEVENT × STUDENT, present or absent
  • REPORT_CARDSTUDENT × PERIOD, published as PDF
  • POSTannouncement for a class or section
  • NOTIFICATIONper user, with mail state
  • AUDIT_LOG, CONTACT_MESSAGEwho did what; messages from the public form
Only one flow crosses all three groups. A teacher creates an EVENT for a class, grades land in GRADE against each ENROLLMENT's student, and the PERIOD that closes freezes the coefficients on CLASS_SUBJECT before the REPORT_CARD is built.

A school year, end to end

The order the platform is used in, from setting up a year to rolling into the next one.

  1. Set up the yearAdmin creates sections, classes, subjects with coefficients, rooms.
  2. CalendarPeriods per section, holidays and closed days.
  3. Import the rosterName-based e-mails; homonyms get a number.
  4. Build the timetableHard conflicts are blocked, soft ones need a reason, free rooms are suggested.
  5. Daily lifeAttendance, homework and exams, grades entered then published, students notified.
  6. Close the periodCoefficients freeze; report cards are generated, edited, published as PDF.
  7. Preview the rolloverShows promotions and copied groups. Writes nothing.
  8. Apply itOne transaction: new year, promotions, groups copied, old year archived read-only.

Who can do what

Every route goes through one ownership check, so students read only their own data and teachers write only to classes they teach.

Student

Reads own data only.

Timetable, homework, grades, absences, report cards, announcements, notifications, personal calendar feed.

Teacher

Writes to classes they teach.

Own timetable, agenda, grade entry and publishing, attendance, groups and « Assigner à », announcements.

Coordinator teacher

Teacher space plus the year structure.

Subjects, coefficients, rooms, periods, calendar days, timetable series.

Admin

Whole school.

Users and roster import, classes, school years, validations, report cards, messages, next-year rollover.
