# Public site in French only

**The platform is French only.** The school decided it: the public pages (home, history, Bac nationale, Bac français,
contact, accessibility statement, sign-in entry), the spaces behind sign-in (élève, enseignant, administration), the
e-mails and the PDF report cards are all in French. The English and Arabic versions that existed before (`/en`, `/ar`,
their translations, the language switcher, the hreflang links) were removed; nothing in the build offers another
language.

Why it matters for the code: there is one language, so there is no language prefix in the URL, no switcher and no
hreflang. The French words are still kept apart from the code, so a school can change them without touching a
component.

## Addresses

| Page | Address |
|---|---|
| Home | `/` |
| History | `/histoire` |
| Bac nationale | `/bac-nationale` |
| Bac français | `/bac-francais` |
| Contact | `/contact` |
| Accessibility statement | `/accessibilite` |
| Sign-in | `/connexion` |

They are declared once, in `apps/web/src/app/i18n/pages.ts` (`PUBLIC_PAGES`, `PATHS`). Every page except the sign-in
page is prerendered (6 static routes). The sign-in page is client-rendered.

## How it is built

No `@angular/localize` and no runtime translation library: the French words are a typed object, loaded as a lazy chunk
with the public and sign-in routes.

| File | What |
|---|---|
| `i18n/lang.ts` | `LANGS` (`['fr']`), `DEFAULT_LANG`, `LANG_META` (direction, `og:locale`), site title |
| `i18n/pages.ts` | `PublicPageId`, the address of each page, the canonical address |
| `i18n/messages.ts` | **`SiteMessages`**: the shape of every interface string (functions for sentences with a value), split into `BaseMessages` (the words every school shares) and `SchoolMessages` (what names the school) |
| `i18n/messages-base.fr.ts` | The shared words (sign-in, contact form, page chrome) |
| `i18n/compose-messages.ts` | Joins the shared words, the school's words and the profile's section names into the `SiteMessages` of `i18n/fr.ts` |
| `schools/<id>/site/messages.fr.ts` | The school's words: page descriptions, hero, history, accessibility statement |
| `school/school-content.ts` | **`SchoolContent`**: the shape of the school's own content (history, tracks, photos' alt text, subjects) |
| `schools/<id>/site/content.fr.ts` | The school's content in French (gathers `school-info.ts`, `tracks.ts`, `photos.ts` of the pack) |
| `school/matieres-text.ts` | The subject catalogue's names and blurbs, shared by every pack |
| `i18n/locale.ts` | `LOCALE` injection token (`SiteLocale`), typed route data (`PublicRouteData`, `publicRouteData()`, `readPublicRoute()`) |
| `i18n/site-head.ts` | `SiteHead` service: sets `<html lang="fr" dir="ltr">`, the canonical link and `og:locale` on the server and after each navigation |

The pack of the school is selected at build time (`SCHOOL`, docs/new-school.md): `scripts/select-school.mjs` points
`school/active/` at it. A component reads its words with `inject(LOCALE).messages` / `.content`.

## Edit a text

1. Find the text: the shared words are in `apps/web/src/app/i18n/messages-base.fr.ts`, the words that name the school in
   `schools/<id>/site/messages.fr.ts`, the school's content (history, milestones, track pages, photo captions) in
   `schools/<id>/site/content.fr.ts`. Subject names are `apps/web/src/app/school/matieres-text.ts`.
2. Edit it, then `npm test` and `npm run build` (the build type-checks every key). `npm run e2e:public -w @cdls/web`
   runs Axe on the public pages.

## Add a page

Add its id to `PUBLIC_PAGES`, its path to `PATHS` (`i18n/pages.ts`), its `pages.<id>` messages (title and description)
in the message files, and a `page()` line in `features/public/public.routes.ts`. If it is prerendered it is picked up by
`app.routes.server.ts` through `PRERENDERED_PAGES`.

## The profile's languages

`profile.json` keeps a `languages` list and the validator still knows the three language codes, so the schema can say
more later. For now every pack says `"languages": ["fr"]`. The per-language fields of the profile (names, address,
affiliation, section labels) still carry values for the other codes that the schema requires; the site never shows
them.

## The contact form

The labels and errors are French, and the **subject and track sent to the API are the French wording**
(`CONTACT_SUBJECTS`, `CONTACT_TRACKS` in `school/contact-mail.ts`): the secretariat reads French.
