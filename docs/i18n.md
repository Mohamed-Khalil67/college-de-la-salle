# Public site in French, English and Arabic

The public pages (home, history, Bac nationale, Bac français, contact, accessibility statement, sign-in entry)
exist in three languages. **French is the source and the default** (no prefix); English lives under `/en`, Arabic
under `/ar`. The spaces behind sign-in (élève, enseignant, administration) stay in French.

> **Status of the English and Arabic text: machine-drafted, not reviewed.** Every English and Arabic string was
> drafted from the French by an AI model. The school must have them read by a fluent person (ideally a teacher of
> each language) before the `/en` and `/ar` pages are announced. Until then the accessibility statement says so
> itself (« first draft that the college still has to review »): remove that line only after the review. Points
> to check in particular: the names of the two baccalaureates (« Egyptian Bac » / « الثانوية العامة » for the
> Bac nationale), the Lasallian vocabulary (« إخوة المدارس المسيحية », « الأخ مدير الكلية »), the founder's
> titles, and every number and date (they are checked by tests against the French, but the wording is not).

## Addresses

| Page | fr | en | ar |
|---|---|---|---|
| Home | `/` | `/en` | `/ar` |
| History | `/histoire` | `/en/history` | `/ar/history` |
| Bac nationale | `/bac-nationale` | `/en/egyptian-bac` | `/ar/egyptian-bac` |
| Bac français | `/bac-francais` | `/en/french-bac` | `/ar/french-bac` |
| Contact | `/contact` | `/en/contact` | `/ar/contact` |
| Accessibility statement | `/accessibilite` | `/en/accessibility` | `/ar/accessibility` |
| Sign-in | `/connexion` | `/en/login` | `/ar/login` |

They are declared once, in `src/app/i18n/pages.ts` (`PUBLIC_PAGES`, the table of paths). Every page except the
sign-in page is prerendered in each language (18 static routes). The sign-in page is client-rendered.

## How it is built

No `@angular/localize` and no runtime translation library: each language is a **typed object**, loaded as its own
lazy chunk with its routes (a French visitor never downloads the Arabic text).

| File | What |
|---|---|
| `i18n/lang.ts` | `LANGS`, `Lang`, direction, `og:locale`, site title per language |
| `i18n/pages.ts` | `PublicPageId`, the address of each page in each language, `alternates()` for hreflang |
| `i18n/messages.ts` | **`SiteMessages`**: the shape of every interface string (functions for sentences with a value) |
| `i18n/messages.fr.ts` / `.en.ts` / `.ar.ts` | The words. `en` and `ar` are typed `SiteMessages`: a missing or misspelt key does not compile |
| `school/school-content.ts` | **`SchoolContent`**: the shape of the school's own content (history, tracks, photos' alt text, subjects) |
| `school/content.fr.ts` | Gathers the French source (`school-info.ts`, `tracks.ts`, `photos.ts`) |
| `school/content.en.ts` / `.ar.ts` | The translations, typed `SchoolContent` |
| `i18n/locale.ts` | `LOCALE` injection token (`SiteLocale`), typed route data (`PublicRouteData`, `publicRouteData()`, `readPublicRoute()`) |
| `i18n/site-head.ts` | `SiteHead` service: sets `<html lang dir>`, canonical, hreflang, `og:locale` on the server and after each navigation |
| `public/public.routes.ts`, `auth/login.routes.ts` | Route factories taking a `SiteLocale`: titles and descriptions from its messages |
| `layout/language-switcher.ts` | The switcher (same page, other language; each name in its own language with `lang`) |

A component reads its words with `inject(LOCALE).messages` / `.content`. `LOCALE` is provided on each language's
routes only, so a component used outside them fails instead of silently showing French.

## Edit a translation

1. Find the text: interface words are in `src/app/i18n/messages.<lang>.ts`, the school's content (history,
   milestones, track pages, photo captions, subject names) in `src/app/school/content.<lang>.ts`.
2. Edit it. Keep facts (years, links, headcounts, photo ids) identical to French: `i18n/i18n.spec.ts` compares
   them and fails otherwise.
3. `npm test` and `npm run build` (the build type-checks every key). `npm run e2e:public -w @cdls/web` for Axe.

**Change the French source** in `messages.fr.ts`, `school-info.ts`, `tracks.ts` or `photos.ts`, then update `en` and
`ar` (the compiler tells you which keys moved; the spec tells you which facts differ).

## Add a language

1. Add it to `LANGS` and `LANG_META` (`i18n/lang.ts`), and its paths to `PATHS` (`i18n/pages.ts`).
2. Write `messages.xx.ts`, `content.xx.ts` and `xx.ts` (copy `en.ts`); add the route lines to `app.routes.ts`.
3. Add its entries to `TRANSLATIONS` and `MESSAGES` in the two spec files. The build fails until every key exists.
4. Right-to-left languages: `app.css` already mirrors the layout from `dir="rtl"`; add a font like Cairo.

## Add a page

Add its id to `PUBLIC_PAGES`, its path in every language to `PATHS`, its `pages.<id>` messages (title and
description) in the three message files, and a `page()` line in `public.routes.ts`. If it is prerendered it is
picked up by `app.routes.server.ts` through `PRERENDERED_PAGES`.

## Right to left (Arabic)

- `<html lang="ar" dir="rtl">` is in the prerendered HTML. Components use **logical properties** only
  (`padding-inline-start`, `inset-inline-end`, `text-align: start`, `margin-inline-*`): never `left`/`right`.
  `components.css` was converted; new CSS must follow (`styles.css` says so).
- Font: **Cairo** (self-hosted, Arabic range only) for Arabic text; Inter and Cormorant keep the Latin words and
  digits. Arabic uses Western digits (0-9), as the school's documents and phone numbers do, and has no
  letter-spacing or italics (they break the joining of letters).
- Mirrored: the hero's scrim, the select's arrow, the timeline's rule and stars, chevrons (`class="flip-rtl"` on
  `<cdls-icon>`). Not mirrored, on purpose: the crest, photos, phone numbers (`.phone-number` forces them left to
  right inside Arabic sentences), the college's name (marked `lang="fr"`).

## SEO

- `<title>` and meta description per page and language (`messages.<lang>.ts`, `pages`).
- `hreflang` for fr, en, ar and `x-default` (French), `canonical`, `og:locale`, in the prerendered HTML.
- The links are root-relative unless the build knows the site's address: Docker passes `PUBLIC_WEB_URL`
  (`deploy/.env`) as a build argument; locally `ng build --define "SITE_ORIGIN='https://example.org'"`.
  **Set `PUBLIC_WEB_URL` for the production image**: absolute URLs are what search engines expect.
- No sitemap yet (needs the production address): to add once `PUBLIC_WEB_URL` is known.

## The contact form

Labels and errors follow the page's language, but the **subject and track sent to the API are always the French
wording** (`CONTACT_SUBJECTS`, `CONTACT_TRACKS` in `public/shared/contact-mail.ts`): the secretariat reads French.
A visitor may write the message itself in English or Arabic.
